# 安装与使用

## 安装包方式（不需要 Node.js）

1. 在项目 Releases 下载 `ov-web-clipper-0.5.1.zip`，不要误选 GitHub 自动生成的源码 ZIP。
2. 解压到准备长期保留的文件夹。解压后的目标目录里应直接看到 `manifest.json`、`index.html` 和 `background.js`。
3. 打开 Chrome，地址栏输入 `chrome://extensions`，开启右上角“开发者模式”。
4. 点击“加载已解压的扩展程序”，选第 2 步的目录。
5. 在 Chrome 工具栏的扩展菜单里固定 OV Web Clipper。点击一次会采集当前普通网页并打开侧边栏；扩展“详细信息”中的“扩展程序选项”可打开完整工作区。

Chrome 可能提示开发者模式扩展，这是手动加载方式的正常提示；请核对项目来源。它不是商店签名安装包。企业策略禁用开发者扩展时需由管理员处理。

## 从源码构建

```bash
git clone https://github.com/pengqiancheng-sys/ov-web-clipper.git
cd ov-web-clipper
npm ci
npm test
npm run build:extension
npm run audit:release
```

按前述 Chrome 步骤加载 `dist/`。需要 Node.js 22.12+。

## 连接自己的 OV

前提：有自己的可用 OpenViking 服务，启用 API Key 模式，具有绑定租户/用户的 Key，且目标 Resource 可写。不要使用 ROOT Key。推荐权限足够且范围受限的 USER Key。

1. 在“连接设置”输入 OV 服务的完整 HTTPS 地址。可以包含反向代理路径前缀，但不要包含账号密码、查询参数、Key 或网页后台路径。HTTP 仅允许本机开发地址。
2. 填入用户 API Key。默认只在本次浏览器会话保存；如勾选长期保存，仅存本机扩展本地存储，非加密保险箱。
3. 选择个人收件箱、个人 sites 或共享项目目录。项目名限 1–64 位文字、数字、短横线和下划线，不接受路径。
4. 点击“保存设置”，再点击“授权此服务器”，处理 Chrome 的站点权限提示。
5. 点击“只读测试连接”，核对服务器返回的账号、用户、角色、版本及目标 URI。此操作只验证读取；目标尚未建立时会检查父目录，**不代表写权限已通过，也不会创建目录**。

验证采用官方 `/health`、`/api/v1/system/status` 和资源 stat/ls 接口，不自动配置你的服务器、模型或权限。身份不一致、ROOT/trusted 模式会阻止连接。

## 收录并验证第一篇文章

1. 打开你有权保存的普通 HTTP/HTTPS 文章，点击工具栏图标。若正文提取不好，先选中文字，再右键选择采集菜单。
2. 在侧边栏检查标题、来源、正文、个人批注。编辑不会丢掉原始采集快照。保存到本地只影响本机。
3. 点击“预览上传到 OV”，核对服务器、身份、目标 URI 与正文。确认后才会上传。
4. 上传走临时文件和 Resource 导入接口，异步处理。点击“查询处理状态”，任务完成后输入与文章有关的问题，点击“检索并回读正文”。
5. 看见命中与原文一致，才表示本次检索及内容校验通过。换种问法、换客户端或换身份仍需要单独验证。

不要用敏感资料做第一次测试。实验文章应放测试范围，服务器侧清理后再检查原文及检索结果；扩展没有删除服务器资源的按钮。

## 常见问题

| 提示或现象 | 处理方式 |
| --- | --- |
| 普通网页不支持 / 没采到正文 | 不支持 Chrome 内部页；切回文章页操作，尝试选区采集；动态内容先等页面展示完整 |
| 没有服务器访问权限 | 在连接设置点击“授权此服务器”，处理浏览器提示后测试 |
| 401 / 403 | 核对用户 Key、租户身份、资源权限；不要改用 ROOT Key 绕过 |
| 返回 HTML 或 JSON 无效 | 核对 OV API 基址、反向代理和服务版本；登录后台网址不一定是 API 基址 |
| 父目录可读，上传失败 | 只读测试没有验证写权限；核对服务端 ACL、配额与模型配置 |
| 状态待确认 / 超时 | 先查询已有任务；不要反复确认上传。服务端受理状态不明时先回读，避免重复资源 |
| 任务完成但检索失败 | 任务完成不等于本次查询命中；核对服务端向量化、当前身份与问题相关性，尝试文章中具体信息，不伪称已经可召回 |
| 已删除的资源仍显示旧回执 | 点击查询状态更新；本地回执是历史状态，不是服务器实时镜像 |
| 更换服务器后密钥消失 | 有意防止把旧密钥发往新服务器，需填新 Key 并重新授权与验证 |

## 更新、保留与卸载

新版本下载后，保持同一个加载目录和扩展身份，先导出重要 Markdown，再替换程序文件并在扩展管理页点击重新加载。路径或身份变化可能导致 Chrome 把它当另一个扩展；不要承诺自动迁移。重新加载后核对本地记录和连接身份再上传。

卸载扩展前导出所需内容；浏览器可能移除本地扩展数据。OV 端已收录内容不会因卸载而自动删除。撤销密钥需在 OV 服务端操作，移除扩展不等于撤销服务器凭据。
